## العربية

مشروع تغليف تطبيقات Windows (`.wapproj`) يبني حزمة MSIX لمتجر Microsoft، للمعماريتين x64 وARM64.

### المتطلبات

- Visual Studio 2026 مع:
  - عبء العمل **‎.NET desktop development**، ومكوّنه الاختياري **MSIX Packaging Tools** (لا يظهر في بحث «المكونات الفردية»؛ فعّله من لوحة تفاصيل عبء العمل).
  - **Windows 11 SDK (10.0.26100)** من «المكونات الفردية».
- أمر `dotnet build` لا يبني مشاريع `.wapproj`؛ ولذلك يبني الـ CI الملف `Itmam.CI.slnf` الذي يستثني هذا المشروع.

### المحتوى

| الملف | الغرض |
|---|---|
| `Package.appxmanifest` | الهوية من Partner Center (المنتج `9P08F7KGRJB0`)، وصلاحية `runFullTrust` فقط، و«التشغيل مع Windows» (`ItmamStartup`) |
| `Strings/ar` و`Strings/en-US` | الاسم والوصف بالعربية والإنجليزية |
| `Images/` | صور المتجر والبلاطات بكل المقاسات؛ تُولَّد بالأمر `dotnet run --project tools/IconGenerator -- --store src/Itmam.Package/Images` |

التطبيق يُنشر مستقلًا (يتضمن ‎.NET 10، لأن المتجر لا يوفّره للتطبيقات المكتبية) ومُترجَمًا مسبقًا (ReadyToRun). حجم الحزمة نحو 67 ميغابايت لكل معمارية.

### البناء

```powershell
# ملف الرفع إلى المتجر (غير موقّع: المتجر يوقّعه):
./tools/Build-Package.ps1                 # → artifacts/msix/*.msixupload

# حزمة موقّعة للتجربة على هذا الجهاز:
./tools/Build-Package.ps1 -Mode Test      # → artifacts/msix/*_Test/*.msixbundle
```

### التجربة المحلية

1. مرة واحدة لكل جهاز: `./tools/New-DevCertificate.ps1 -Trust`
   - تُنشأ شهادة موقّعة ذاتيًا في مخزن شهادات المستخدم، بمفتاح غير قابل للتصدير، **دون أي ملف ‎.pfx أو كلمة مرور على القرص**.
   - يُضاف جزؤها العام فقط إلى «الأشخاص الموثوق بهم» على الجهاز (يطلب موافقة المسؤول).
2. `./tools/Build-Package.ps1 -Mode Test`
3. التثبيت: انقر نقرًا مزدوجًا على ملف `.msixbundle`، أو:
   `Add-AppxPackage artifacts\msix\Itmam.Package_1.0.0.0_Test\Itmam.Package_1.0.0.0_x64_arm64.msixbundle`
4. التشغيل من قائمة «ابدأ» ← «إتمام». وإلغاء التثبيت من الإعدادات ← التطبيقات، أو `Get-AppxPackage NasserAlmadi.563063310BE3D | Remove-AppxPackage`.

ملاحظة: داخل الحزمة يكتب التطبيق في `%LOCALAPPDATA%\Itmam` الخاص بالحزمة، ويُحذف عند إلغاء التثبيت. لكن إذا كان المجلد الحقيقي موجودًا مسبقًا على الجهاز (من نسخة تطوير غير مغلَّفة)، تستخدم الحزمة ملفاته كما هي ولا تحذفها.

### الفحص قبل الرفع

شغّل Windows App Certification Kit (يحتاج صلاحيات المسؤول) على حزمة x64:

```powershell
& "${env:ProgramFiles(x86)}\Windows Kits\10\App Certification Kit\appcert.exe" test `
    -appxpackagepath src\Itmam.Package\bin\x64\Release\Itmam.Package_1.1.0.0_x64.msix `
    -reportoutputpath artifacts\wack-report.xml
```

نتيجة الإصدارين 1.0.0.0 و1.1.0.0: نجحت كل الفحوص إلا اثنين. «Blocked executables» يبلّغ عن نصوص مثل `cmd` داخل ملفات ‎.NET نفسها وداخل بيانات القاموس المضغوطة، وعن `Process.Start` الذي تفتح به صفحة «حول» الروابط في المتصفح؛ إتمام لا يشغّل أي برنامج آخر. وتحذير «DPI Awareness» لأن WinForms يضبط PerMonitorV2 عند البدء (`ApplicationHighDpiMode`) لا في ملف البيان.

### عند كل إصدار جديد

- ارفع `Version` في `Package.appxmanifest` (مثل `1.0.1.0`؛ الرقم الرابع يجب أن يبقى 0 في المتجر).
- لا تغيّر قيم `Identity` ولا `PublisherDisplayName`: يجب أن تطابق Partner Center حرفيًا.

## English

Windows Application Packaging Project (`.wapproj`) that builds the MSIX for the Microsoft Store, for x64 and ARM64.

### Requirements

- Visual Studio 2026 with:
  - the **.NET desktop development** workload and its optional **MSIX Packaging Tools** component (it does not
    show up in the Individual components search; enable it in the workload's details pane);
  - **Windows 11 SDK (10.0.26100)** from Individual components.
- `dotnet build` cannot build `.wapproj` projects, so CI builds `Itmam.CI.slnf`, which leaves this project out.

### Contents

| File | Purpose |
|---|---|
| `Package.appxmanifest` | Partner Center identity (product `9P08F7KGRJB0`), `runFullTrust` only, start with Windows (`ItmamStartup`) |
| `Strings/ar`, `Strings/en-US` | Name and description in Arabic and English |
| `Images/` | Store and tile images at every scale, generated by `dotnet run --project tools/IconGenerator -- --store src/Itmam.Package/Images` |

The app is published self-contained (it carries .NET 10, which the Store does not provide for desktop apps) and
ReadyToRun-compiled. The package is about 67 MB per architecture.

### Building

```powershell
# Store upload (unsigned: the Store signs it):
./tools/Build-Package.ps1                 # → artifacts/msix/*.msixupload

# Signed bundle for testing on this PC:
./tools/Build-Package.ps1 -Mode Test      # → artifacts/msix/*_Test/*.msixbundle
```

### Testing locally

1. Once per PC: `./tools/New-DevCertificate.ps1 -Trust`
   - creates a self-signed certificate in the user's certificate store with a non-exportable key, **with no .pfx
     file or password on disk**;
   - adds only its public part to the machine's Trusted People (asks for administrator approval).
2. `./tools/Build-Package.ps1 -Mode Test`
3. Install: double-click the `.msixbundle`, or
   `Add-AppxPackage artifacts\msix\Itmam.Package_1.0.0.0_Test\Itmam.Package_1.0.0.0_x64_arm64.msixbundle`
4. Start it from Start → "Itmam". Uninstall from Settings → Apps, or `Get-AppxPackage NasserAlmadi.563063310BE3D | Remove-AppxPackage`.

Note: inside the package the app writes to the package's private `%LOCALAPPDATA%\Itmam`, removed on uninstall.
If the real folder already exists on the PC (from an unpackaged development build), the package uses those files
as they are and does not remove them.

### Checking before uploading

Run the Windows App Certification Kit (needs administrator rights) on the x64 package:

```powershell
& "${env:ProgramFiles(x86)}\Windows Kits\10\App Certification Kit\appcert.exe" test `
    -appxpackagepath src\Itmam.Package\bin\x64\Release\Itmam.Package_1.1.0.0_x64.msix `
    -reportoutputpath artifacts\wack-report.xml
```

Result for 1.0.0.0 and 1.1.0.0: every check passed except two. "Blocked executables" reports strings such as `cmd` inside .NET's own
files and inside the compressed dictionary data, and the `Process.Start` the About page uses to open links in the
browser; Itmam never starts any other program. "DPI Awareness" warns because WinForms sets PerMonitorV2 at start-up
(`ApplicationHighDpiMode`) rather than in the manifest.

### For every new release

- Raise `Version` in `Package.appxmanifest` (e.g. `1.0.1.0`; the fourth number must stay 0 for the Store).
- Never change the `Identity` values or `PublisherDisplayName`: they must match Partner Center exactly.
